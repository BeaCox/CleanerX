# `v0.1.0-alpha.1` release checklist

Status: pre-tag preparation

Release type: unsigned engineering-preview prerelease

This checklist is the evidence record for the first CleanerX alpha. Do not publish the draft GitHub Release until every applicable item below is complete. Items that require tagged artifacts remain intentionally unchecked until the release workflow creates the draft.

## Scope and identity

- [x] The maintainer confirmed that the repository history, author identity, branding, and bundled image assets may be public.
- [x] The release is named `v0.1.0-alpha.1` and is presented as an engineering-preview prerelease, not the supported `v0.1.0` milestone.
- [x] Cargo workspace, frontend package, Tauri configuration, mock update status, and version-facing tests use `0.1.0-alpha.1`.
- [x] The updater public key is committed; `TAURI_SIGNING_PRIVATE_KEY` is configured as a GitHub Actions secret and is absent from the repository.
- [x] The changelog records the user-visible scope, irreversible operations, updater boundary, and known limitations.

## Pre-tag automated evidence

- [x] `pnpm install --frozen-lockfile` succeeds without changing a lockfile.
- [x] `make check` passes on the release-preparation tree.
- [x] Gitleaks reports no secret findings in the reachable Git history or release-preparation diff; the maintainer separately confirmed the repository's public-information boundary.
- [x] `pnpm audit --prod` reports no known production dependency vulnerabilities.
- [x] RustSec reports no known vulnerabilities; accepted maintenance or unsoundness warnings are listed in the release review.
- [x] The dependency-license inventory contains no unknown or release-incompatible license.
- [x] The protected-data, path-safety, backup fault-injection, restore rollback, journal-boundary, recovery, i18n, and updater tests remain in the passing test set.
- [ ] Required Linux, macOS, and Windows CI checks pass on the release-preparation commit; the exact tag reruns them below.

## Repository controls before tagging

- [ ] The GitHub repository is public and `main` remains the default protected branch.
- [ ] Private vulnerability reporting is enabled and the public advisory link resolves.
- [ ] Secret scanning, push protection, the dependency graph, and Dependabot alerts are enabled.
- [ ] The tag target is the reviewed `main` commit and the working tree is clean.

## Tagged workflow and draft assets

- [ ] The release workflow accepts the SemVer tag and confirms every version surface matches.
- [ ] Product CI reruns successfully from the exact tag.
- [ ] macOS arm64, macOS x86_64, Linux x86_64, and Windows x86_64 release builds succeed.
- [ ] Every expected manual installer, updater payload, `.sig`, `latest.json`, lockfile archive, build-metadata file, and checksum file appears exactly once in the draft.
- [ ] `latest.json` contains version `0.1.0-alpha.1`, the four intended updater targets, HTTPS URLs for the exact tag, and non-empty signatures.
- [ ] Every staged asset matches `CleanerX_0.1.0-alpha.1_SHA256SUMS.txt`.
- [ ] Bundles contain no development URL, private absolute path, local preference, real Agent data, journal, backup archive, signing private key, or backup identity.

## Native draft verification

- [ ] Both macOS architecture artifacts launch on a clean supported system; Finder **Open** or System Settings approval is sufficient without disabling Gatekeeper.
- [ ] The Linux AppImage and `.deb` launch on a clean supported environment; the AppImage updater path and `.deb` manual-update explanation are correct.
- [ ] The Windows MSI and NSIS installers launch on Windows 10/11; SmartScreen disclosure and the passive NSIS updater path are correct.
- [ ] Read-only scan, bounded detail loading, review dialog, backup listing, settings persistence, and explicit read-only degradation are exercised on packaged builds.
- [ ] Disposable Agent homes complete the applicable cleanup, optional backup, restore, interruption, and post-operation verification cycles without changing protected fixtures or source trees.
- [ ] Keyboard navigation, visible focus, Chinese and English, light and dark system themes, and reduced-motion behavior receive an alpha acceptance pass.
- [ ] A tampered updater payload or signature is rejected, no check occurs at startup or on a timer, and installation still requires separate check and install actions.

## Publication approval

- [ ] Release notes lead with alpha status, irreversible-deletion risk, unsigned/not-notarized status, compatibility limits, and checksum-versus-publisher-identity guidance.
- [ ] Release notes link the changelog, compatibility matrix, security policy, exact source commit, and this checklist.
- [ ] Remaining observations are either documented limitations or release blockers with the affected mutation capability disabled.
- [ ] A maintainer has reviewed the complete draft and changed it from Draft to Pre-release.

## Current dependency-audit notes

The pre-release Rust dependency review must explicitly revisit the Tauri Linux dependency chain. The most recent pre-preparation RustSec run reported zero vulnerabilities, sixteen unmaintained transitive crates, and the `glib 0.18.5` unsoundness warning `RUSTSEC-2024-0429`. These warnings do not widen CleanerX's cleanup allowlists, but they remain tracked release risk and must not be described as a clean warning-free audit.
